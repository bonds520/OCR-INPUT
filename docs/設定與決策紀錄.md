## 3. 主檔規格（`金紙秤重表.xlsx`）

- 每個作業日一組分頁：`神明-YYYYMMDD`（白色）、`先靈-YYYYMMDD`（黃色）。
- 續頁：`神明-YYYYMMDD-2`、`-3`…；續頁編號 91–180、181–270…（每頁 3 直欄各 30）。
- 分頁版面（沿用檔內空白範本「神明」「先靈」）：
  - `B1` 日期真值，樣式 `s=5`（numFmt 176 = `m"月"d"日"`）→ 顯示「9月5日」
  - `E1` 金紙總類 = 類別字串（神明(白色)/先靈(黃色)），系統帶入
  - `C33` 頁次「第N頁」（編號 60 正下方，新增第 33 列；列印落在第一頁範圍內）
  - 重量格：`B3:B32`／`D3:D32`／`F3:F32`
  - `H2` `=COUNT(...)` 袋數、`I2` `=SUM(...)` 重量（各頁自算，不跨頁加總）

## 4. 核心決策

| 決策 | 內容 |
|---|---|
| 寫 XLS 方式 | **外科手術式 zip 注入**（B 方案）——只重寫 4 個索引檔（`[Content_Types].xml`、`workbook.xml`、`workbook.xml.rels`、`docProps/app.xml`）與被改動的分頁；其餘（125 張舊分頁、126 個 `printerSettings*.bin`）逐 byte 保留。不使用 openpyxl 整份重寫。 |
| 產生分頁 | 網頁手動輸入日期（可多筆，逗號分隔），神明/先靈各可設頁數（預設 1）。固定成對產生。已存在略過，頁數不足才補續頁。一律 append 到分頁尾端。 |
| OCR | 本機 vLLM，整張送、縮圖長邊 1600、compact JSON（只回有值的格）。單張 35–95s。逐格準確率約 93%。表頭「類別」判定不可靠。 |
| 複核 | 一律人工逐格對照原圖；低信心/離群/塗銷格紅框標示。目標分頁一律人工確認（不信任 OCR 類別）。 |
| 回填 | 只寫 `B/D/F` 欄；`H2/I2` 公式不動（`fullCalcOnLoad=1` 讓 Excel 開檔重算）。塗銷格留白。重量 `0.1–30 kg` 外標紅。已有資料的分頁預設拒絕覆蓋，需勾「覆蓋」（整頁清空後重寫）。 |
| 批次上傳（Plan C） | 多檔上傳 → 背景逐張 OCR → 總表逐列人工複核 → 「寫入已確認列」一次交易（單次備份、單次存檔；部分失敗照寫其餘）。路由用「作業年份（前端填）+ OCR 月日 + 類別」比對現有分頁給建議，比不到留空。同分頁被兩列指到 → 標紅擋寫。批次狀態存記憶體，TTL 2 小時，服務重啟需重傳。上傳影像用完即刪。 |
| 列印檢視 | 產生分頁成功後，網頁出現「列印本次新增」按鈕（**按鈕觸發**，只含**本次新增**、不含略過者）。另有**重印**：同分頁下方輸入日期（可多筆）→「查詢」列出該日已存在的分頁（前端讀 `/api/sheets`，只列符合 `類別-YYYYMMDD[-N]` 者，歷史錯字名稱不列）→ 勾選 → 「列印所選」開同一個 `/print`→ 新分頁開 `/print`，載入後自動呼叫 `window.print()`。版面由分頁名決定（類別、月日、頁次、編號範圍），**不讀 xlsx**，對照 Excel 範本：日期/金紙總類合併格、3 組編號/重量×30 列、頁次在編號 60 正下方；A4 直向，邊界左右各 6mm、上 9mm，列高 8mm，字級 18pt，字型 PMingLiU→新細明體。只印 A:F 三組（現行 Excel 列印因 G:I 溢出會多一頁）。微調改 `app/printview.py` 的 CSS 變數。備案：瀏覽器列印縮放/邊界不穩時，升級為伺服器產 PDF（同版面定義）。 |
| 安全 | 寫入前偵測 `~$金紙秤重表.xlsx`（Excel 鎖檔）則拒絕；所有寫入經單一鎖序列化；每次寫入前備份。 |
| 範圍外（暫不做） | 排程自動產生、Odoo 整合、列印用 PDF、手機 App、帳號權限、修改歷史分頁、掃描資料夾輪詢。 |

## 5. API

| 方法 | 路徑 | 用途 |
|---|---|---|
| GET | `/` | 網頁 |
| GET | `/print?sheets=A,B,…` | 空白表列印檢視（A4，每分頁一張；分頁名須為 `類別-YYYYMMDD[-N]`，最多 100） |
| GET | `/api/sheets` | 現有分頁清單 |
| POST | `/api/generate` | 產生分頁 `{dates[], god_pages, spirit_pages}` |
| POST | `/api/ocr` | 單張辨識（multipart `image`），不寫檔 |
| POST | `/api/write` | 單張複核後寫回 `{sheet, weights, overwrite}` |
| POST | `/api/batch` | 建立批次（multipart `year` + `images[]`），背景 OCR |
| GET | `/api/batch/{id}` | 批次狀態（輪詢） |
| GET | `/api/batch/{id}/item/{iid}/image` | 該項暫存影像 |
| POST | `/api/batch/{id}/item/{iid}` | 單項複核 `{sheet, weights, overwrite}` |
| POST | `/api/batch/{id}/write` | 寫入所有已確認項（一次交易） |
| DELETE | `/api/batch/{id}` | 清除批次 |

## 7. 已知限制

1. OCR 手寫準確率約 93%，且部分錯誤不會被標低信心 → 必須逐格人工複核。
2. 表頭「類別」判定常錯（先靈↔神明）→ 目標分頁一律人工確認。
3. 表頭日期無年份、續頁無頁次資訊 → 批次路由的續頁會被建議到第 1 頁，需人工改指 `-N`。
4. 批次狀態非持久化，服務重啟該批次需重傳。
5. 無帳號權限，限內網。
6. openpyxl 存檔會丟印表機 `.bin` —— 已改用外科手術式注入規避；但**若日後有人用 Excel 開主檔另存**，Excel 自己的存檔行為不受本系統控制。
